### 任务计划预览的间接I/O闭环

导入页代理继续追踪发现，`submission_issue` 和 `matching_current_task` 每次渲染都会进入同一个 `build_plan`，间接执行课程库 `is_dir`、标记检查、文件夹记录重载、本地视频 `is_file`；服务配置又经 `config_for_refs → check_dispatch` 读取停用标记。设置页用于显示的 `is_service_stopped` 自身也有 `exists` 回退，首轮检查漏掉了这些间接路径。

- `build_plan` 现在明确区分 `Preview` / `Submission`。前者只读已加载的课程库状态、文件夹索引和服务快照；后者继续重新检查实际位置身份、文件夹、本地来源及服务停用标记。
- `config_for_preview` 只生成不含密钥的界面配置，不能授权发送。原 `config_for_refs`、`check_dispatch`、`resolve_for_execution` 和密钥解析仍在实际提交/执行边界使用；设置页的显示调用改用纯内存停用状态。
- `options::resolve` 的默认 provider 提示在 Linux 上会探测设备/PATH；校验前对配置副本填入已检测的 provider，环境检测未返回时的临时显示提示也不再探测文件系统。`model_dir_from`、`validate_asr_with_auth` 的本次调用经源码追踪只做路径展开、数值、模型名和URL校验，不读取模型文件。
- `task_component_outcomes` 不再在 render 中回读 `manifest.json`。课程库代理在后台刷新里补齐缺失历史结果，并在发布前匹配任务、来源、课程库和结果路径；任务列表和工作台只读已载结果。
- 新增 `plan_preview_uses_loaded_storage_but_submission_rechecks_identity_and_folders`：过期界面快照不能让错误课程库身份或已删除文件夹通过真实提交。
- 新增 `preview_uses_loaded_services_but_dispatch_rechecks_external_stop_markers`：界面可以保留已载快照，独立写入的停用标记仍必须阻止实际提交和执行。

这些改动已经格式化并通过差异格式检查，编译与测试由主代理统一执行。没有把静态审查或受控线程测试写成用户电脑卡死已复现。
