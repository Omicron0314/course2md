# 17:22–17:29 截图后的审查失效复盘

用户在已交付的 Design Preview `20260909.5`（代码 `9ec2f6e`）中继续发现明显问题。上一轮“没有新的必须修问题”和“本轮修正已完成”的设计判断撤回。测试、构建及安装记录仍是各自执行过的事实，不能证明这些画面的产品设计合格。本记录只总结原因，没有修改或重新安装应用。

本次依据是用户提供的九张不同截图（第一张重复展示了一次）、当前共享布局源码和上一轮审查原文。用户标注用于理解问题；提出的具体改法仍需放回整页的信息关系中判断，不能再次逐项机械照搬。

## 缺陷的共性：控件有了样式，信息和操作没有组成完整的单元

| 画面中的问题 | 共同原因 |
| --- | --- |
| 开关停在页面中部，关联说明框铺满整行 | 同一设置的标签、值、说明采用不同边界。说明的面积和边框比实际操作更醒目，用户需要自己把分散的部分对应起来。 |
| “编辑 AI 服务”在选择器下方；同一服务的测试、编辑和停用分散 | 只给独立按钮安排位置，没有给“这个对象及其相关操作”定义共同操作区和换行条件。 |
| 关于页名称、说明与链接的可见起点不同；部分行高和间距不协调 | 以父容器坐标代替实际图标、文字和按钮内容边界。布局矩形对齐后，没有继续检查视觉中心、内边距和组内节奏。 |
| 模型仓库名挤在窄标签列中折成数行，完整路径横跨右侧 | 把独立资源当成普通键值字段。模型名称、状态、位置和打开动作本应属于同一个资源单元；固定列宽无法替代内容类型判断。这是默认模型会产生的真实内容，不能只归为极端长字段。 |
| 完成任务有技术事实和原始日志，却缺少封面；阅读页用大区域重复四项“已完成” | 按程序能提供什么安排信息，缺少对当前用户任务的取舍。识别课程和打开产物更重要；正常成功的内部细节不应抢占阅读空间。把日志折叠起来仍未解决它是否应出现在这里的问题。 |
| 大块状态信息显眼，常用查找只有需要再展开的入口 | 视觉强调与使用频率、当前任务的关系脱节。用户常用的动作和真正有必要处理的异常没有得到相称的位置。 |
| “已就绪”与“运行环境就绪”等状态混用 | 状态回答的层次不一致：一处是能否使用，一处是依赖是否存在。需要统一面向用户的问题，同时保留运行环境和模型状态的真实差异，不能为了文案整齐而全部写成可用。 |

因此，对齐不仅包含几个元素的左坐标；它还包含共同边界、对象与操作的接近关系、同类行的中心线，以及整页的视觉轻重。统一应发生在完整设置项、资源卡和任务结果这些层面。开关本身仍保留合适的标准大小；状态徽章和按钮也不需要被强行做成同一种控件。

## 为什么上一轮没有找出来

1. **审查被已有修复清单引导。** 我给代理补充了已做的改动、预期结果和剩余收尾项，后续复核越来越集中于证明这些点已修好。部分代理也承担了所审查区域的实现。主代理没有充分重新质疑页面结构和信息选择；这是我组织审查和采纳结论的问题。

2. **把容纳得下当成设计成立。** 审查反复确认可见、没有重叠、能够滚到、存在共同列。旧设置审查明确接受编辑按钮占第二行，因为它仍在同一个控件列；旧阅读审查把生成信息的四行完整显示当成关闭依据。这些结论没有回答动作是否应在同一组、信息是否值得占据这个空间。

3. **共享抽象本身带着错误，我又用局部规则为它辩护。** `settings_form_row` 限制控件宽度后，把说明作为全宽的兄弟元素；`info_callout` 默认铺满父容器。skill 已经写了层级和就近关系，但我把“就近”简化成上下相邻，把“一致”简化成各自列起点相同。在这些局部尺寸与整组关系冲突时，我没有按上层原则重新判断布局。即使所有调用者复用组件，这个错误也会整齐地扩散。

4. **把下载规范和应用规范混为一谈。** 官方资料讲目的、层级和关联关系；我主要把它们转成尺寸、圆角、图标、字号和固定列。随后又用这些自行制定的规则检查自行实现的界面，缺少能够否定当前方案的整页参照。资料数量不会自动变成设计判断。

5. **覆盖范围与用户的常用状态脱节。** 大量精力花在极小窗口、大字号和单个组件的边界；已登录账号、完整真实模型路径、完成任务和展开后的阅读信息等常用组合没有得到同等深度的判断。某些未审查状态被记入边界，最后却仍作出了完成结论。用户不应承担把常用状态一一标注出来的工作。

6. **用可计数的产出制造了过度确定的结论。** 242 张图、201 项测试、原子提交、哈希和安装身份说明工作发生过。它们不回答信息是否有用、布局是否协调、常用操作是否直观。我把局部问题关闭外推成整体足够好，最后一句“Goal 已完成”尤其不成立。

## 后续判断必须改变的顺序

先确定这个页面服务的用户任务、必须展示的内容及可删除的内容，再组成完整设置项、资源或结果单元；接着决定单元之间的层级和宽度，最后才调整图标、字重、间距和动画。

对每个单元先检查“这是什么、当前怎样、能做什么、操作作用于谁”，再检查同类单元的共同边界与视觉中心。说明跟随自己的设置项，编辑跟随自己的当前值，资源动作跟随对应资源。宽度不足时按完整单元重排。

复核需要先在没有修复清单提示的情况下独立看整页、指出最影响理解的地方，再核对具体回归项。审查者需要能够否定整个分组或删除无价值信息。最终判断由主代理承担，不能由“没有代理再提出问题”替代。

这些原则约束的是下一轮设计与复核方式；本记录没有宣称截图中的缺陷已经修复。
