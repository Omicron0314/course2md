**全产品视觉复核记录 · 2026-09-09 · 分批证据与收口判断**

本轮从用户拒绝的 c5a00ae 三张引导图重新评价。拒绝版本的问题已经超出个别控件的尺寸，集中在主题语义、整页构图、选择信息和共享控件契约。之前把页面能运行、测试通过、控件没有越界，与设计已经成立混在了一起。它们分别提供工程和行为证据，不能替代完整画面的判断。各轮问题的当前处理状态以文末收口表为准。

本草案依据当前 [设计 skill](../../.agents/skills/course2md-design/SKILL.md)、[共享体系](../../.agents/skills/course2md-design/references/system.md)、[任务与连续性](../../.agents/skills/course2md-design/references/interaction.md)及[设置构图](../../.agents/skills/course2md-design/references/settings.md)。本阶段只读源码、原图和新旧截图，没有操作用户窗口、修改实现或提交。工作树同时有其他代理修改；以下七项用于定位拒绝版本及早期实现的问题源头，新构建的具体状态以后文分批证据为准。

**证据分层**

- 本轮直接证据：用户提供的 Engine、AI、Model 三图，均为 Tokyo Day 浅色。原文件分别为临时目录中的 `codex-clipboard-ea5db6bb-1d5a-4f9d-934d-fcdeff98a248.png`、`codex-clipboard-09c614d3-59b6-4c7e-a51b-edeee63b8910.png`、`codex-clipboard-c80591ac-99a7-448b-9c7e-1055cb82cd89.png`。它们支持本轮引导的颜色、布局、选择及焦点问题。
- 源码范围：`views.rs`、`theme.rs`、`palettes.rs`、`choice_group.rs`、`onboarding.rs`、工作台/库/任务/阅读器、五个设置类别、关于与模型诊断；还读取了当前 `.deps/component` 的 Input、Button、sizing 和 focus ring 实现。这里的源码判断不是原生绘制结论。
- 历史对照：重新查看 `docs/design-review-2026-09-09` 中的 96 工作台、34 库、74 任务、93 Reader、86 外观、87 生成设置、80 服务表单、79 存储、75 应用、76 诊断。文件名中的 final/current 仅是历史命名；这些图不是本轮构建，更不是本轮通过证据。此前 flow 的运行记录仍能说明当时的行为，不能覆盖新的视觉修改。

**根因一：主题颜色没有经过产品语义转换**

三张原图的窗口标题、页面标题、字段、输入正文和状态几乎都蓝色。强调色没有稀缺性，普通文字看起来也像可点击内容。这个结果不是某个引导标签误用 accent：审查时 `palettes.rs::TokyoDay` 直接给出 `text=0x3760bf`、`muted=0x52679b`；`theme.rs::palette_colors` 将它们映射到 `INK/GRAY`，`sync_component_theme` 又同步到 foreground、按钮和输入。`views.rs` 的引导与正常根视图均继承 INK，因此影响所有页面和组件。

需要在共享主题语义层区分正文、辅助文字、链接/主动作、选中态和状态色。配色名称、用户已保存的浅/深选择及主题来源应保留；不能靠逐页覆盖黑色解决根因。主题预览也必须反映实际应用的角色映射。Tokyo Day 是本轮已证实的失衡，其他配色是否有类似问题须逐一原生查看，不能由一个深色主题推断。

验证准则：遮住按钮形状后，正文仍应读成正文；恢复形状后，主要动作、当前位置与错误各自容易辨认。正文色不与动作色争夺注意力，辅助文字仍能正常阅读。这是本轮产品层级判断，不扩成专项可访问性审计。

**根因二：引导按窗口剩余高度排版，没有按当前任务形成完整区域**

Engine 只有两项选择，Model 只有身份、状态和少量动作，却在整窗上部排成细长文字列，前进动作落到窗口最底部。`onboarding_page` 的外层和 `setup-scroll` 都使用 `flex_1`，footer 是独立末尾子项。44rem 只限制了横向宽度，不能修正纵向失衡。固定动作在长表单中有用途，但不应把简短步骤的操作与其内容隔开半个窗口。

应先形成一个完整的初始设置区域：产品身份/当前任务、必要选择、反馈与前进动作连续出现；短内容按自然高度，长内容达到可用高度后再滚动。用户提出“小窗口”反映的是需要集中注意力、降低无用空白，不能直接简化为增加一个带边框的浮层。可以使用有明确边界的任务面板或合适的对话层，具体形态需要整屏原生对照决定。面板不应再嵌套无用途的卡片，也不能为了充满它补说明文字。

验证准则：普通、宽窗和矮窗中，首先看到的是正在完成的选择；下一步留在其阅读路径中；出现真实错误或下载状态时不把操作挤出可达区域。大字号是重新排版条件，不能简单把固定面板放大到窗口之外。

**根因三：机械复用设置行，代替了选择信息和表单构图**

`settings_form_row` 的左列 `flex_1`，右侧为 `360/14 rem` 槽。在宽设置 pane 中，剩余空间进入左列，把短标签和开关拉远；历史 86/87 已显示这种关系。引导改成 44rem 后缩短了间距，但仍把首次理解问题做成“标签—一个隐藏菜单”。Engine 原图只显示 Automatic、Qwen3 1.7B 等结果，新用户看不到模型选项的有效差异。多句文字解释步骤安排，却没有帮助选择模型。

需要先按内容定组，再决定组内布局。偏好列表可以用稳定的标签/控件轴；需要输入与纠错的服务表单，可以使用紧凑的字段列；首次模型选择应让少量有意义的选项及差异可比较。模型的推荐理由、适用情形与实际下载需求来自现有能力/模型数据，不能编造性能或准确率承诺。互斥选项保留单选语义，不能因为批注写“复选框”就允许同时选择多个默认引擎。

右侧控件不必都拉满，但整组宽度和对齐应由共同容器决定，不能又为某个 switch 单独增加一个更窄的常量。菜单和选项卡只是信息承载方式，不能用统一胶囊形状代替设计选择。

AI 原图还暴露了任务支持不足：模型 ID 完全依赖手输，用户希望从服务地址获取候选；Model 原图指出缺少 Bilibili 登录入口。这两项是能力与入口问题，不是给字段补图标能解决。后续若提供模型列表，应有明确的获取动作、真实请求及失败/手输退路；Bilibili 账号作为可选来源能力，应保留已登录状态和跳过路径，不能成为无关视频的强制前置步骤。

**根因四：选择状态仅靠相近色面，静态“有选中值”不等于看得清**

AI 原图的 API Key/无需认证两项很难迅速辨认当前项。审查时 `SingleChoiceGroup` 的选中面用 `ACCENT_SOFT`，浅色值由 surface 与 accent 混合 10%；轨道由 canvas 与 INK 混合 4.5%。Tokyo Day 下两块底色接近，正文又都偏蓝，进一步削弱差异。源码中的选中值、单选语义和动画进度都不能证明这个视觉关系成立。

共享选择态需要稳定可辨认的表面与文字/标记关系；聚焦、悬停、按压叠加时仍保持“哪一项被选中”。主动作最强，导航和偏好选中仍应较安静。不能把所有选中项都填成主按钮蓝色，也不能只加更明显的 hover 来掩盖静止状态。

验证准则：从未选到已选、已选+hover、已选+pressed、已选+focus 分别拍摄或连续观察；十套配色都看真实文字与相邻未选项。静态截图覆盖静态区别，不能声称动画或按压通过。

**根因五：控件实际绘制范围没有进入容器契约**

AI 原图中 Model ID 的右侧焦点环确实被截断。当前组件的 `ThemeStyled::focus_ring_style` 在边框外画 3px 环，还计入边框偏移；它不是普通布局宽度的一部分。`setup-scroll` 的内容满宽贴住裁剪边界，设置的 `settings-content-scroll` 也有相同构造。外层有页面 gutter，不等于滚动区内部为焦点留了空间。

应在共享滚动/表单容器关系中保证实际焦点绘制范围完整，或采用一致的内部焦点处理。不能用取消焦点反馈来让截图看起来没有溢出，也不能只给 AI 最右输入补一次 padding。库搜索、服务编辑、设置展开输入、Reader 查找、重命名和模态首末控件均需检查。普通键盘行为保留，不扩展审计范围。

验证准则：在原生窗口里让位于滚动区四个边缘的实际控件获得焦点；完整看到轮廓，文字位置和邻居不随 focus 移动；滚动揭示后仍完整。仅测量布局矩形不能覆盖外绘焦点。

**根因六：共同控件只有外壳统一，内部尺度和字形没有统一验证**

审查时 `theme::control/text_input` 主要规定外层高度、圆角和字号；Input 仍继承组件 Medium 的固定 10px 水平 padding。`primary_pill/outline_pill` 为固定 16px，而选择项 padding 使用 rem 随字体增长。这样在 200% 字号时，边框高了、字大了，输入和普通按钮的内部呼吸空间却没有跟着变化。外层都高 40px 不能证明字、图标与圆弧的关系一致。

还需要注意组件内层：Button 在自己的 label 容器中应用 `button_text_size(self.size)`、居中、间距及 `overflow_hidden`；外层文字样式不必然控制该层。当前默认尺寸未由源码单独证实有字号错误，因此应作为明确的原生核验点，不把“调用了共享函数”当成核验结果。手工 child 组成的多行任务卡、媒体和正文区也不能继承普通按钮的固定内容高。

应在共享实现中定义普通动作、纯图标动作、选择控件、单行输入的实际文字与图标布局；媒体、多行内容和 Textarea 保留各自自然内容行为。保持项目的 40px 基线，但不要把所有外框都变成同一个高度或形状。页内的特殊尺寸若确实必要，需要说明角色，而不是为了修某张截图临时覆盖。

验证准则：同一原生测试区域并排放真实 Button、Input、SingleChoiceGroup、纯图标按钮与下拉按钮，比较外框、字体、基线、图标和内部留白；再在 100/125/150/200% 及窄窗复看。测试只提供工程证据，最后仍要看实际绘制。

**根因七：审查以局部修复为单位，没有把完整产品当作一个阅读系统**

历史截图和源码呈现多种密度：宽设置的标签/控件分离，服务编辑是一整列长输入，Reader 又叠加返回、标题、两组元信息和工具栏。Reader 的 `reader-controls` 最多可占 45% 高度；历史 93 中加上通知后，首屏主体很晚才出现。这个安排需要用真实图文重新判断，不能只因为正文仍有剩余高度就认定阅读体验足够好。

工作台关注输入与当前结果，库关注可阅读内容，任务关注处理中断与结果，Reader 关注正文，设置关注低频默认项。它们不必每一页都一样，但页标题、主动作、状态、正文和次级详情的相对地位必须稳定。当前源码仍有任务页 24px 标题等局部规格，与其他 28px 页面角色不完全一致；是否调整应服从这一整体层级，不能再只按数字逐项对齐。

本轮应先看同一构建、同一主题和字号的完整页面并列，再查几何与边界状态。不要只选深色/短文本/单条数据，不要将旧截图的 final 字样或测试总数转写成设计结论。原图中的“没有对齐、没有图标”需要理解为信息组织不清；添加大量图标也不会自动形成层级。

**本轮采用的准则及来源**

- 用分组、阅读顺序和空间关系区分重要信息与次级信息；让相关内容与操作靠近；在窗口和字号变化后保持可辨认的关系。依据 [Apple Layout](https://developer.apple.com/design/human-interface-guidelines/layout)。本轮判断针对整页构图，不照搬其中其他平台的具体尺寸。
- 引导帮助用户尽快完成真实任务，提供合理默认值，可跳过、可返回，并推迟非必要配置；下载不应使整个产品无法使用。依据 [Apple Onboarding](https://developer.apple.com/design/human-interface-guidelines/onboarding)。这不指定必须用三步、浮窗或某一种卡片。
- 设计应服务于任务，保留用户自由，使用一致反馈和明确层级。依据 [Apple Design principles](https://developer.apple.com/design/human-interface-guidelines/design-principles)。这些原则用于选择方案，不是给既有布局补一个官方背书。
- 选中、hover、focus 等状态可以组合，并在组件间一致应用。依据 [Material States](https://m3.material.io/foundations/interaction/states/overview)。本项目继续沿用共享体系中的 Material 选择原则与克制胶囊；不因为 Material Expressive 更新而额外加入变形动画。
- 40px 控件、28/18/14/12px 字号、默认 360px 且随字号缩放的控件槽及其他尺寸都是项目适配值，不是上述官方规范的精确规定。现有数字若损害本轮任务与构图，需要在共享体系中一起修正。

**仍需处理的具体问题**

1. **AI 用途开关的空间归属不清。** [07](<07-ai-tokyo.jpg>)、[11](<11-ai-input-focus.jpg>)、[12](<12-ai-test-passed.jpg>) 中，每个标签与自己的开关相隔约 180px，而左开关与下一项“生成课程摘要”只隔约 18px。虽有两列逻辑，完整画面更容易把开关读到下一项。源码相符：`setup_service_content` 中两个用途组各自 `flex_1`，标签又 `flex_1`，把开关推到组尾。应让标签与开关形成靠近的完整组，或使用一致的纵向读轴；不为单个开关再加孤立宽度补丁。复核应同时看两项开/关及换行后的归属。
2. **首次选择的作用范围仍未说清。** [06](<06-engine-tokyo.jpg>) 已能区分本机/在线路线及模型取舍，但标题“选择识别方式”和介绍都在解释识别过程，没有说明这些是后续任务复用的默认值。“保存并继续”表明保存，仍没有交代范围。应在标题或一句介绍中直接说明默认范围；不增加另一块帮助卡或技术说明。
3. **任务空态的层级和动作语义弱于同级库空态。** [19](<19-tasks-empty.jpg>) 的状态标题与说明视觉重量接近，唯一主动作却是返回箭头和“返回工作台”。源码始终导航到工作台，并不恢复实际来处；从库或设置进入也显示“返回”。与 [18](<18-library-empty.jpg>) 对照，宜共享清楚的空态标题角色，并让主动作表述“导入视频”这一实际任务。这里不要求补一个重复页标题或把空白填满。
