# 原生产品审查证据摘录

本目录保存 2026-09-09 的独立审查文档、核验 JSON 和原生原图。首批归档含 36 张原图，后续补做与安装证据按实际操作追加。数量是归档规模，不是通过项数。[reviewed-screenshots.json](reviewed-screenshots.json) 逐项记录准确文件名、SHA-256、字节数、像素尺寸、画面实际状态和限制。

所有原图均已直接查看，复制过程保持字节不变，没有裁切、缩放、重新压缩、拼接或覆盖旧失败画面。主代理操作原生应用；本次整理没有操作 GUI、运行 cargo、修改产品代码或提交 Git。

## 如何读取版本和结论

- 报告按原文复制，保留各自形成时的事实、失败和未访范围。早期报告中的“待复拍”不会因后来出现截图而被改成通过。
- v5 服务卡诚实显示旧默认但缺少更新入口；v7 原图进一步展示就近动作、确认和更新后的默认关系。v5 的修复 401 是拒绝状态，v7 的“仅保存”仍是未补做状态。
- v5 仅补导出后笔记库误报部分完成的问题保留在原报告；v6 重开的笔记库与独立导出文件核验是后续证据。文件字节核验不等于浏览器视觉验收。
- `v5-storage-move-result.jpg` 实际是正在复制，完成状态在 `v5-storage-move-complete.jpg`。`v6-migrated-note-focused.jpg` 才是本次选取的稳定阅读结果。
- v6 查看器分别为图片和同期文字模式；v5 搜索首末命中仍保留短窗上下文偏少的限制。某一静态帧可读不证明全部查询、滚动、放大、取消或异步行为。

较早的[设置覆盖清单](settings-model-storage-coverage.md)是当时持有证据的快照。后来补入的写入失败、迁移、失联、任务修复等画面及主代理的操作记录，应按具体状态补证，不能把旧清单的所有未知一次性关闭。最终综合判断由主报告承担。

## 原始上下文与归档边界

原采集目录为 `/tmp/course2md-product-review-2026-09-09`。复制报告中出现的临时绝对路径、相对路径和未入选截图名，仍指向这个原始采集上下文；本目录不是临时课程库或工作目录的镜像。未复制配置、凭据、导出 HTML／转录正文、任务工作目录和未请求的 AX 正文。指定的 `final-export-byte-evidence.json` 按原文保留，其正文样例来自合成夹具。

主代理明确排除的 `v6-migrated-note-readable*` 与 `v6-storage-restored*` 没有归档，因为它们不是稳定的最终画面。请求中的图库搜索项按实际文件名 `v5-narrow-gallery-search.jpg` 收录。此次指定文件均存在，清单的 `missing_requested_files` 为空；没有补绘或用其它状态冒充缺失证据。

本目录仅含选定原图。十种配色等更广泛的逐图观察保留在[共享外观独立审查](shared-v4-cross.md)，其全部原始图片没有在这个约 35 张的摘录中重复归档。截图尺寸、哈希以及报告中的测试数量都不构成全产品验收声明。

后续补入 [设置与引导最终跨审](final-settings-first-cross.md)、[默认变更范围核验](v7-default-verification.json) 和[仅保存范围核验](v7-save-only-verification.json)。仅保存核验是提交前的时间点；之后主代理另行点击开始补做，其新增任务不属于仅保存动作。

最终归档追加到 48 张原图，包含 v8/v9 补做连续性与实际安装版。新版本放在旧版本上方的提示，只适用于用户主动留在旧正文或查看器的情况；同页正常补做会直接打开新版。见[跟随边界复核](reader-follow-static-review.md)与[安装核验](installed-preview-verification.json)。
