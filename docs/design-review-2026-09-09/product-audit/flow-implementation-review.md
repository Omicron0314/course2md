## 异步与输入边界复核

`source_editor_open` 只改变输入区域可见性，不会隐式取消当前转换或更改来源。改变输入仍走现有 invalidation：取消当前读取、增加请求代数、清理已解析来源；异步回调继续核对请求代数、原始输入、Draft id 与 revision。开始转换的单次意图、准备完成后的继续、旧来源无权提交这些现有守卫没有因收起输入而旁路。

当前没有亲自真实访问首次启动、修复凭据、队列恢复或高字号原生状态。它们仍是待验项；单元测试及编译结果不替代上述产品流程证据。

## v1 原生交叉审查后的第二轮

设置审查者对真实冷启动 `v1-01-start.jpg` 的交叉审查推翻了“部分完成卡已足够精简”的实现判断：它仍有总状态、逐项原因、红色失败阶段三层重复；已知 401 后仍并列旧服务重试；工作台主体还是旧任务。阅读审查者的引导交叉审查也指出首步直接进入没有保存当前引擎、首步缺模型准备状态、模型发现字段拆散等问题。

已进一步处理：

1. 新增显式进入方法 `prepare_workbench_input`，由主代理接冷启动恢复后、主导航和导入动作。它只将准确关联且未被修改的可读 Complete/Partial 或 Cancelled 输入换成按保存默认建立的新空表单；暂停、运行、不确定、缺可读产物与用户修改后的输入都保留。它先保存、再复核、事务成功后更新输入；失败停留并保留原状态，避免在 render 中清理输入或写盘。对当前 `config-normal` 真实旧 Partial 的只读比对证实其字段满足这个条件，实际清理效果仍由 v2 原生验证。
2. 明确区分需要改配置的 AI 错误与可以重试的短暂失败。401/403/404/400/422 配置证据优先修复；429、超时、500 不改成配置修复；未知外部结果仍走显式重发；已交给后续尝试的旧任务不再恢复。工作台与任务详情在已知配置错误时不再并列“仅补校对/摘要”旧配置按钮。对应共享判定交由 reader/最近笔记入口复用。
3. 工作台 Partial 去掉重复的失败阶段表与诊断折叠段，仅保留具体缺项和原因、阅读、修复、任务详情。详细日志仍在用户主动进入的任务异常详情中。
4. `finish_task` 只在本次完成状态成功保存后标记瞬时结果；横条显隐与寿命由主代理的共享界面决定，不对历史记录初始化。
5. 引导首步显示模型资源描述与实际异步检查状态，不自动下载；自动选择策略从固定引擎网格分开，硬件条目的状态明确为“运行环境已就绪”；第 4 步名为“模型准备”。AI 开关旁说明它用于后续转换并发送转录文字。已有本机引擎记忆从保存的设置恢复，保存也复用新的 `GenerationPreferences::select_provider`。
6. 首步“直接开始使用”先执行同一路径保存引擎；只有成功进入下一步才结束引导。引擎保存或服务检查失败不会直接结束。模型候选和手填的单字段合并由 settings 审查者统一完成。
