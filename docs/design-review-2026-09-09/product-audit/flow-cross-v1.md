# 流程原生跨审 v1

独立审查者：reader agent。本轮不审自己实现的阅读区域，也不修改流程代码。依据当前设计技能、实看截图与 AX，再检查相关源码；未继承其他 agent 的修正说明或旧通过结论。未操作 GUI，未作专项无障碍审计。

已逐张查看：v1-01、v1-11、v1-12、v1-13、v1-14，以及后续新到的 v1-15、v1-16、v1-17、v1-18（均为本目录 jpg 与同名 ax.txt）。截图可证明当帧层级与可见内容，不能独立证明保存、下载完成或返回时的数据语义。

## 需要先修的结论

1. **P1，v1-01：冷启动工作台仍是旧 Partial 任务详情，主输入完全缺席。** 顶部说“把视频整理成笔记”，实际主体是旧课程的结果卡，开始新视频只有卡下方的安静“转换其他视频”。一个已经得到可读结果的旧任务，不应继续占有新任务输入。保留“最近笔记/需要处理”的短摘要与阅读/修复入口，恢复可直接输入视频的主区域。当前截图不能接受；后续修改必须重拍冷启动、普通回工作台、真实运行/暂停/不确定/未提交分别如何保留。
2. **P1，v1-11 + 源码：首步“直接开始使用”可能丢弃刚刚明确选择的识别方式/模型。** `save_setup_engine` 才提交引擎选择；该按钮直接调 `finish_onboarding`，后者只标记 setup_completed，`leave_onboarding` 再从已存偏好刷新。若用户先改为 CPU 或较小模型再“直接开始使用”，不能仅因按钮位于左侧就推定用户知道刚选内容不会保存。选择应被明确应用，或按钮明确表达“跳过本次设置，使用已有默认值”。这是代码确定的路径风险，必须实测变更选择→该按钮→实际新任务使用值，不能用截图中的默认未改状态证明无问题。
3. **P1，v1-13/15：AI 开关没有就近解释普通生成的外发范围和作用范围。** 页头只说用于校对/摘要；页脚说明“检查仅发送内置示例”说的是测试请求。开启“自动校对文字/生成课程摘要”后，后续笔记的转录文字会发给所选服务，这一实际后果需要在开关附近明确，且应说明是后续生成的默认设置。用户刚在首步选择“本机识别”，不能要求他自行推导“音频本机处理”和“文字随后送 AI”之间的边界。保留测试样例/可能计费说明；补充真实正文使用后果，不要把它误写成整个视频会上传。

## 信息架构建议

默认路径应帮助用户开始一份真实笔记：选择本机/已配置服务并采用已知可用默认值 → 进入视频输入。AI、Bilibili 与模型准备应按当前选择或真实障碍逐步出现。若保留四步引导，至少把它明确设为可选设置，并避免让同一个模型在第1步被选择、第4步才第一次得知不可用。

本批图中的圆角、标签和基本行列已经相对统一，但不能用它们掩盖上述任务语义问题。先解决主任务归属、选择与保存的关系、AI外发范围，再修重复行和空白。

## 截止本报告仍缺的证据

- 首步改引擎/模型后“直接开始使用”的真实持久化与后续执行；在线语音分支的取消/测试失败/返回。
- 模型列表失效、空、慢，用户继续手工改模型 ID 时晚结果不能覆盖。
- AI 表单测试中离开/取消；失败后范围化恢复；测试通过后改开关/模型旧结果失效；保存失败不宣称成功。
- Bilibili 登录流程返回，及完全不需要它的本地用户路径。
- 模型准备离开后的后台连续性、暂停/恢复、失败和完成，以及“稍后准备”后真正的视频转换。
- 修正后的冷启动与普通返回，区分旧终态、真实运行/暂停/不确定、未提交输入；最后必须到可读笔记。

这些未访问状态不记通过。后续新截图可继续补在本报告，但已指出问题必须以新原生结果与实际操作验证解决。

## 补充实看 v1-19、v1-20

- **v1-19-first-model-prepared-state：文件名不代表准备完成。** 画面与 AX 实际是“正在准备模型 / 下载 Qwen3 模型文件 / 27% · 已用 55 秒”，仍有“暂停准备”，所以这张只作为真实进度到达的证据。百分比、阶段和主操作均能阅读；对比 v1-18，数据到达后内容落进原先预留空白，消除了那一帧最明显的大空洞。不过“正在准备模型”和“下载 Qwen3 模型文件”仍可合并为一个明确阶段，前者的活动符号与进度条也不必双重强调。可以保留动作位置稳定，但应让没有进度的状态本身完整自然，不能仅靠后来填满为其辩护。
- **v1-20-first-background-prepare：退出向导后确实出现主输入，且进度由 27% 到 29%。** 这组连续截图支持准备至少在离开前后继续推进，主任务“视频链接 / 本地文件 → 开始转换”清楚，比 v1-01 旧终态占有工作台更符合首次使用。正文外发说明在视频输入下方可见，也说明它是实际生成会使用的设置；它仍不能补救首次 AI 开关作决定时缺少作用范围的问题。
- **P2，v1-20：后台工作重新成为页面顶部最大信息块。** 一个已被用户明确放到后台的下载，占据导航下方约 140 像素并领先于“把视频整理成笔记”，含模型 slug、后台状态、下载阶段、时间和整行进度条。建议压成一行 `Qwen3 1.7B 正在下载 · 29%` 加“查看进度”，需要暂停/细节时进入已有状态页。主输入保留当前中心地位。至少将内部 `qwen3-1.7b` 与向导的 `Qwen3 1.7B` 使用同一显示名。
- **仍需实际操作：** 这张主输入旁的“字幕不可用时自动识别视频声音”没有说明本机模型仍在准备时会如何衔接。不能仅因“开始转换”可点就判定流程已完成；应各走一份有字幕视频与一份必须识别的本地视频，证明前者可以继续、后者明确等待或准备模型，而且已有后台下载不被第二个任务错误替换。还需首次准备真正完成、暂停/恢复、失败、重入结果页；本批 19、20 张均不能记为完成态通过。

## 已补模型最终状态：v3-first-model-result

已实际查看 `v3-first-model-result.jpg` 与 AX。页面明确为“Qwen3 1.7B / Apple 原生 / 模型已验证加载 / 可以开始使用”，主动作是“返回应用”。结合此前真实下载与后台推进，现已补上本次准备流程的最终加载状态，不能再把这条路径写成只观察到 27% 或 29%。它区别了仅有模型文件与实际加载验证，用户能据此决定返回应用。

该图仍来自旧 v1 首次使用应用二进制，只补充这次真实下载与加载的终态证据，不替代新版向导、后台提示、窄窗布局或真实转换验收。“重新验证加载 / 重新检查 / 模型详情”仍为次级动作；在已完成页可将重新检查合并进详情，避免把日常用户又引回诊断，但当前主按钮“返回应用”没有被阻断。
