# 首次使用、工作台、转换与任务的独立初审

审查日期：2026-09-09。审查者：fresh_flow_audit。此记录先于本轮实现；不是验收通过记录。

我读了 AGENTS.md、course2md-design 技能及 system / layout-and-type / states-and-motion / interaction 参考。看过用户原始截图 `/Users/aac6fef/Desktop/Screenshot 2026-09-09 at 17.28.05.png`、`17.28.12.png`，以及 composition-evidence 中引导、工作台、处理中、取消和部分完成的原生截图；独立追踪了当前源码。未操作 GUI，未把以前的审查结论当本轮证据。历史 capture 说明该状态的可见构图，不证明安装版 20260909.5 的行为。用户明确要求保留默认引擎、AI 检查、Bilibili、模型准备这四项可重开的引导，因此建议改进相关性和直接开始入口，不删除引导。专项无障碍审计不在范围内。

最重要的判断：当前页面把配置事实和后台步骤作为主体，视频与可读笔记只是这些记录的附属入口。加一张封面、藏起日志还不够；必须按“我要读什么、现在能读什么、需要我解决什么”重排流程。

## 具体问题

1. **P1：已有可读正文的部分完成状态仍挡在工作台。** `check12-11-final-partial-result.jpg` 中正文已保存，但主按钮是“仅补校对”，阅读笔记排第三且为次按钮。`import_ui.rs:208` 只把 Complete 视为可自动打开的结果；`:2372` 把 Partial 保留在任务卡。用户的核心价值已经可用，附加服务失败不应迫使先浏览失败流程。应直接打开可读正文，把校对/摘要未完成及局部恢复留在笔记旁。真正无法读取正文的状态继续留在恢复界面。

2. **P1：鉴权失败没有与补做绑定的修复路径。** 同一截图明确说 API Key 被拒绝。`task_ui.rs:2523` 在工作台只提供“仅补”与阅读；`workspace.rs:826` 的补做直接沿用 original.plan，包含旧服务绑定。用户修改默认服务后再点“仅补”仍可能使用旧配置。冻结已提交任务是正确约束，但界面必须提供“修复 AI 服务并补做”，把新服务版本明确用于新的局部任务；不可让用户反复盲重试，也不可要求重新识别整个视频。此问题有源码链路依据，最终必须用真实的“失效凭据→修复→仅补成功”原生流程确认。

3. **P1：任务列表是可折叠配置记录，不是任务概览。** 用户的两张原图中，封面和可读内容摘要缺失；保存到/文字来源/AI 域名占据主要面积，11 个完成步骤与原始日志成为独立大段。`task_ui.rs:1712` 的行标题只有标题、时间、徽标，`:1803` 以后才把阅读放入展开内容。完成任务至少要再点一次展开才能读。应让真实视频封面、标题、结果状态和直接阅读组成一条任务行；日期和内容量作辅助，参数与诊断另列可选详情。不能只将现有配置卡左边再塞封面。

4. **P1：任务分组和数量没有表达用户待办。** `task_ui.rs:1709` 对全部任务简单倒序；`:1657` 用 `!state.finished()` 计算“未完成”。`workspace.rs:264` 把 Partial 算完成，可能出现“0 个未完成”同时卡片显示“部分处理未完成”；已由后续任务处理的 Paused 父任务又会继续计数。进行中、需要修复、已结束应分别呈现；被后续任务替代的处理记录应进入该任务的历史，不占用户待办数量。单个任务为空不证明十多个任务时仍能找到需要操作的内容。

5. **P2：首启引导在用户接触内容前就要求理解较多实现名词。** `check07-01-engine.jpg` 展示本机/在线、自动引擎、Qwen 1.7B/0.6B/Whisper 三种模型；接着是服务地址、认证、模型 ID、Bilibili 登录、模型下载。四项引导本身是用户明确需求，应保留，但“稍后设置”隐藏了其实可以直接使用的事实，“Whisper：兼容 Whisper 模型”也没有给选择理由。应在每一项都明显允许进入应用，保留已保存的选择；默认自动检测可用引擎，模型替代项按有依据的资源/兼容说明展开。不要把额外信息全部变成独立边框面板。

6. **P2：工作台同一视频出现多个身份区，控件的承诺也不完整。** 选中文件行、视频摘要、处理中任务标题都重复同一个视频。`new_page` 总是加入 `box_source_input`；`source_editor_open` 仅控制“收起输入/更换视频”标签，没有控制输入区域可见性，因而“收起输入”没有实现承诺。输入解析完成后应由一个带真实封面的来源区接管上下文，并把更换放在同一区；处理中保留来源身份，减少独立文件条和重复标题。

7. **P2：常规运行和完成都持续暴露工程诊断。** `task_ui.rs:2463` / `:2014` 无论是否失败都加入处理历史与原始日志。已完成步骤数量既不说明笔记内容，也不帮助继续任务；原始日志示例是 tokenizer、CoreML、safetensors 等内部信息。正常完成不展示；失败时先给原因与恢复，诊断放到“技术详情/复制诊断”之后。进度仍需真实显示当前阶段和可测量分母；我没有将历史截图中 AI 100%列为当前未修复问题，因为当前 `task_stage_progress` 已针对 AI 请求改为等待服务返回结果。

8. **P2：局部选择的来回操作会丢失明确引擎。** `import_ui.rs:1805` 将“回到本机识别”无条件写成 provider=0。已经选择 CPU 或 Apple 原生的人切到服务再切回来，会失去原显式选择。引导已有来回保留模型/引擎的逻辑，工作台也应保留本机分支的最后明确选择，并在开始新视频时按默认设置恢复。

9. **P2：缺少必要组件时的建议没有直接维修入口。** `task_ui.rs:797`–`:806` 的错误要求去设置找到应用与诊断、FFmpeg 或 yt-dlp；`conversion_recovery` 对这类错误只提供重试，没有定位该问题的动作。这种失败应直接带到对应修复位置并说明如何返回当前视频，而非让用户在设置里寻找。该点需与设置页实现协调，不能只润色错误句子。

## 建议分组与取舍

| 页面/状态 | 首要区域 | 次要区域 | 移走或删除 |
| --- | --- | --- | --- |
| 引导 | 本步骤与当前选择；主要下一步；清楚的直接进入应用 | 已保存状态、适合当前路线的模型或服务配置 | 不适用硬件、重复推荐句、每段一张说明面板 |
| 空工作台 | 视频链接或本地文件、一次开始 | 当前生成方式简述、可展开选项、最近笔记 | 为填空间增加装饰卡、平台信息与来源控件的重复解释 |
| 来源已选 | 一个真实视频身份区、开始或必要决策 | 本次选项摘要及展开调整 | 多处相同文件名和更换按钮 |
| 处理中 | 来源封面/标题、当前真实阶段、暂停/取消 | 同时处理其他内容的入口 | 常驻所有已完成步骤和日志、无关的服务参数表 |
| 部分完成 | 可读正文 | 具体失败项、修复该项配置与仅补 | 以失败卡做结果落地页；要求重新生成整篇 |
| 任务 | 需处理、进行中、已结束；每行直接动作 | 日期、结果内容量、可选处理信息 | 工程步骤作为主信息；所有记录一列无分组；完成后常驻日志 |

应保留：一键开始后的自动元数据/字幕/组件准备；明确字幕模式不静默变成识别；任务配置快照；有实际内容的封面；可读部分结果；停止与恢复的真实状态；外部不确定请求的明确重发决定；后台完成不抢页面。不要为了让列表“整齐”统一展示所有字段，也不要机械执行“每个标签都加图标”使内容和动作同等抢眼。

主内容边界可以仍使用共享外边距与有限宽度，但任务列表和表单不必共用同一个狭窄内容模型。原图的上方单个 900px 左右大配置框配上大量空白，问题主要是框内信息价值和层级，而不是单纯宽度。大字号截图即使没有溢出，若首屏只看到“保存到/文字来源/AI 处理”而看不到阅读，仍然失败。

## 必须真实访问的原生状态

1. 干净首次启动；直接进入应用；四项引导保存/跳过/回退/重新打开；已有配置重开后保留选择。
2. 第一条有字幕的视频：一次开始，自动读取、直接到正文；无 AI 服务时普通转换仍能完成。无字幕且无本地模型的任务：在当前来源旁准备、暂停、继续并抵达正文。
3. 多视频合集必须选择具体视频；登录失败后打开 Bilibili 登录再返回；登录取消；元数据和字幕读到一半换源；旧响应不覆盖新源。
4. 已有笔记再次输入：先见到正确封面/标题/已存在版本，直接打开或明确生成新版本；重复点击不生成重复任务。
5. 进行中离开工作台到设置，后台完成不抢页面；从任务列表直接打开结果；回到同一输入可继续追踪。
6. 校对或摘要鉴权失败，正文直接可读；修复的是当前补做用的服务，新任务只补失败部分；旧笔记和旧任务保持可追溯。修复编辑取消/保存失败不能建立补做或改默认设置。
7. 外部结果不确定：重发显示真实内容范围和费用后果；阅读已有正文始终可达；离开后不自动重发。
8. 暂停请求、停止中、已暂停、取消请求、已取消、重新打开应用恢复，分别验证状态与按钮承诺。
9. 混合队列（运行、等待、失败、部分完成、已完成、已取消、后续处理链），验证分组、待办计数、阅读快捷入口、封面缺失时的自然退化。
10. 正常/窄/宽窗口及 100/125/150/200% 字号；检查行动是否仍在相关内容旁，不能只检查没有溢出。普通键盘操作和既有系统偏好按原行为保留。

上述动态状态本次独立初审均未亲自运行；主代理独占 GUI 完成原生行动轨迹。本报告只给问题和待验证标准，不宣告通过。
