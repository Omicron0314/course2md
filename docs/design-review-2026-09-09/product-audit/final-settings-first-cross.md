# 设置与首次使用最终跨审

审查者：reader agent；这些设置与引导实现不属于本人负责区域。本轮按当前 course2md-design 的任务、布局和状态约束，先实看指定原生截图，再核对 AX 与有关源码。未操作 GUI、运行 cargo、修改产品代码或开展专项无障碍审计。截图只证明可见状态，源码只证明实现路径；没有把主代理的修正说明或旧报告的通过结论当作本轮验收。

**最新状态：F1、F2 已由文末 v7 原图与保存验证闭环关闭；已加载模型页的 v6 实图也已补齐。以下 v5 发现保留为审查历史，当前结论以末尾追加记录为准。**

## 结论

v5 的默认识别决策、服务/模型对象归属和存储位置已经能服务实际使用，未看到必须重做整页的新问题。仍有一个应修的状态文案矛盾，以及一个修复后的后续默认选择缺口。已验证加载页的重复成功框和自动导出取用说明，当前源码有后续修正，但需要 v6 原生图后才能关闭。

### F1 · P2 · “仅保存”后的修复弹层仍把保存描述成开始补做

证据：`v5-scoped-service-401.jpg/.ax.txt`、`v5-scoped-save-only.jpg/.ax.txt`，以及当前 `desktop/src/settings_ui.rs` 的 `service-editor-scope`、`service-tested-not-saved`。

弹层顶部固定写“保存后补做这篇笔记的失败部分”，但它实际提供“仅保存”。仅保存完成后，底部已经正确说“服务配置已保存，尚未开始补做”，主动作也正确变为“开始补做”；顶部旧句仍在。AX 同时保留成功测试卡里的“保存服务后使用这些更改”，这时配置已经保存。这不是发起了错误请求的证据，而是同一对象两处状态互相矛盾，会让人不确定刚刚是否已经再次提交文字。

建议：顶部说明修复对象和范围，明确只有“保存并补做/开始补做”才重新发送失败部分；保存成功后，测试结果说明不再要求重新保存。固定底部的请求范围/可能计费说明与当前动作一致。保留“仅保存”与后续显式提交两个动作的真实区别。

关闭条件：新原生未保存、401 拒绝、仅保存成功三态，标题区域与底部对“是否已提交”的表述一致；仅保存后无新任务，点击开始补做才新增相应任务。已有 JSON 支持原始计划与全局生成设置不变，这一良好行为应保留。

### F2 · P2 · 新服务已通过，但未来任务仍使用旧配置时缺少就近下一步

证据：`v5-settings-service-default-relationship.jpg/.ax.txt`。同一服务卡展示新的 `fixture-summary`、AI 校对通过、生成摘要通过，同时把“默认仍使用旧配置 v3 · fixture-model”放在灰色模型元信息中；卡上动作只有测试、编辑、停用。源码 `service_card` 确认没有相邻默认选择入口。

这里诚实保留旧默认是正确的，不能为减轻困惑而让一次笔记修复悄悄改全局设置。但对接着要处理下一份视频的人，页面只告诉他新旧配置不一致，没有说明在哪儿把已修好的配置用于以后。版本号本身也不能解释影响。

建议：出现该差异时用“以后生成仍使用旧配置”这样直接的作用范围说明，附安静的“更改默认服务”入口，跳转并定位到已有默认服务选择；或提供明确的“用于以后生成的笔记”操作。避免另造版本管理页，也不自动提交/修改已有任务。

关闭条件：从这张差异卡可以识别未来任务仍用旧配置，并到达明确选择新默认的现有位置；取消保持原默认，接受只改变之后的工作。若主代理决定此入口留作后续，应保留为已知的可发现性限制，不能写成已经完整消除困惑。

### F1：关闭

`v7-scoped-save-only` 顶部已明确“配置已保存。点击「开始补做」后才重新发送这篇笔记的失败部分；默认服务保持不变”。底部同步说明已保存但未补做，并把发送后果绑定到当前“开始补做”按钮；AX 中成功测试区域也变为“配置已保存，尚未补做这篇笔记”，不再要求用户保存已经保存过的配置。顶部、滚动区测试结果和固定动作现在对同一状态一致。

### F2：关闭

`v7-service-default-action` 将“以后生成的笔记仍使用旧配置 v3 · fixture-model”单独放成一行，同行提供“用于以后生成…”。新服务的名字/模型与这个后果同属服务卡，用户无需先理解版本管理或自行寻找生成设置。

`v7-default-confirmation` 明确比较“当前默认：127.0.0.1 · v3 · fixture-model”与“更新为：恢复校对服务 · v4 · fixture-summary”，同时说明以后生成将采用它、已有笔记和已提交任务保持、此次不会开始补做；“保留原默认”和“用于以后生成”含义具体。`v7-default-updated` 显示该配置为“默认服务”，旧配置提示和更新入口退出，不留下已经失效的操作。

`v7-default-verification.json` 记录取消时三个文件未变；接受后 workspace 和 generation options 未变，只有默认 llm 版本绑定改变。本次独立重比 `v7-default-before` 与当前 normal 配置，workspace 与 generation 仍完全相等，14 个已有任务及其计划都未改变，defaults.asr 仍为空，defaults.llm 确实从图示旧版本指向新版本。可据此关闭发现、取消、接受及作用范围这条具体路径。

限制：本轮没有新开一份真实视频来重新执行新的默认服务，结论限于选择和持久化绑定；也没有把此接受成功态扩大为默认配置写盘失败时的保证。
