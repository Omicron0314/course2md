# 剩余页面的任务路径复审

审查者：settings_shell。日期：2026-09-09。

依据：本轮更新后的 `course2md-design`、`references/system.md`、`settings.md` 与 `interaction.md`。从真实任务和反例追踪页面、状态与回调；没有把主代理列出的修改当作验收条件。

本记录主要依据源码检查；后续另查看主代理提供的原生截图 `18-single-start-complete.png`，其证据范围见下方补充。本轮没有操作 GUI、运行 Cargo 或执行 Git。先独立发现问题，随后按主代理明确授权修改了默认目的地、AI 覆盖复位、阅读器离线视频、课程库显示偏好的失败反馈与完成页；这些修改属于作者复查，不能称作已经独立通过的原生验收。

## 发现与处理

| 优先级 | 可复现的用户反例及根因 | 最小修正与当前状态 |
| --- | --- | --- |

| P2 | 在课程库切列表/卡片或分组时保存失败，控件已经变化，却没有当前位置的失败/重试说明。`save_library_presentation` 写入未用于显示的 `settings_status`，绕过共享提交反馈。 | 已按授权改用 `application_edit_base` 与 `commit_application`，只改两个库布局字段，保留其他未保存的 Application 修改；工具栏下方固定显示共享 Application 错误、重试和详情。Store 原本会保存 intent，顶栏也可能出现问题指示，因此此处不是“数据完全丢失”，而是缺少当前位置的明确反馈。 |

| P2 | 开始受损坏生成设置阻挡，重置该组成功后清障，却没有与普通 `commit_generation` 相同的 continuation。 | 已报告主代理补接成功后的继续；不能靠自动轮询重试未修复错误。 |

主代理另定位了 AI“恢复默认”仅赋值却未清 override 的问题，并授权本代理补 `Draft::reset_ai_overrides`：只恢复校对/摘要/视觉字段、移除三种 AI override，保留其他覆盖和服务引用。测试再调用后续 `inherit`，检查默认变化确实生效。此问题的独立发现归属主代理，本代理负责实现及作者复查。

## 验证交接

本代理已做的本地检查只有 Rust 源码解析与 owned 范围格式化；新增测试代码尚待主代理统一运行。

原生应重点追踪：A 提交后切 B 默认并生成下一条；未提交 A 的选择不被 B 默认覆盖；配置/设置同步失败再恢复时只提交一次正确计划；开始前修改或取消后修复均不启动；打开两个版本时离线文件不串用，删除文件后点击能得到缺失反馈；断网使用已保留视频；显示方式保存失败时不用离开课程库即可重试。多主题、多字号、宽窄窗口及弹层完整视图仍须主代理原生验证，不能由本记录替代。
